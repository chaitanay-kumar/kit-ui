# Login parity

Validated baseline in batch 47. Integration review, merge/deployment and final user QA remain outstanding.

The native Login replaces the generic cancellable schema form with the React card's actual interface and behavior. `scripts/angular-login.ts` composes native Form primitives and Button; `packages/angular/src/login.css` preserves the card, glow, typography, fields, dividers and optional actions. Caller-owned loading and error inputs remain external. `onSubmit` receives the source email/password/rememberMe payload after synchronous validation; returned promises are ignored by the component. Fields and social actions remain editable/usable during loading. The component adds no automatic authentication, cancellation or loading ownership.

Required/email/length validation and per-field error clearing follow the source exactly. Remember state and password visibility persist through prop changes. Optional forgot/signup actions receive their native click event at runtime, preserving the source's callback invocation despite its parameterless public callback type; social callbacks receive github/google. Their declared provider union also includes apple, but the source renders no Apple button. Numeric-zero logos preserve the source's visible zero rather than rendering the default logo or suppressing it. Native template content replaces custom React nodes. The desktop sm:p-8 default survives an unconditional p-4 customization, following the source's responsive class behavior.

Focused evidence includes 12 desktop/mobile behavior cases, 10 paired geometry/style cases and two byte-identical whole-card numeric-logo screenshots. Tests cover exact validation messages and clearing, Enter submission, unchanged field values after submission/failure, pending callbacks without automatic loading, externally disabled submit buttons, editable fields, password toggles, optional content/actions and unbound callback arguments. Layout variants cover default/custom content, loading/server error, minimal content and root utility overrides. Loading spinners are paused at the same CSS animation phase before comparing geometry.

The component uses source spring presence for inline and server errors; Form evidence covers interrupted exits, node retention and disposal. The package contract verifies validation/payloads without transport-owned loading and source dependency closure, including the native Button implementation. The consuming demo owns a local timer and clears it on destruction; it exercises failure recovery, loading and optional actions without sending credentials anywhere.

Source accessibility limits remain explicit: email/password labels are visible but lack htmlFor/input-ID associations. Inline validation has alert roles; the server error banner does not. Password toggle buttons have tabIndex -1. These are documented rather than silently presented as implemented accessibility guarantees. Native events and Angular templates/refs are framework equivalents; physical devices, Safari/Firefox, SSR/hydration, exhaustive accessibility and real authentication integrations are outside the recorded checks.

See [batch evidence](batch-47-integration.md) for required baseline and strict consumer results. Metadata now accurately describes external loading, ignored submit promises, error ownership and the actual accessibility boundaries.
