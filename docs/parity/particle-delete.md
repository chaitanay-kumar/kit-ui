# Particle Delete parity

Validated baseline in batch 48. Integration review, merges/deployment and final user QA remain outstanding.

The native implementation replaces the generic delayed action with resource cards, mount-owned item state, per-card delete buttons, a global deletion lock, count/restore controls and the source empty state. Restore reads the latest initialItems input; changing that input alone does not replace current items. Item icons, truncation, responsive padding, keyboard-native buttons and accessible delete names follow React. The source's unused tag/meta fields remain in the item type.

`particle-delete-engine.ts` ports the actual DOM/canvas utility: computed-style cloning into SVG foreignObject capture, procedural background/border fallback, alpha-aware pixel sampling, device-specific step defaults, DPR cap, particle limits, all four delay patterns and the same per-frame physics. A fixed, aria-hidden, non-interactive canvas overlays the captured bounds while the source element is temporarily hidden. Completion restores visibility, releases the frame/canvas and invokes the completion callback. Reduced motion uses the source 150ms fade; unavailable capture uses its 200ms fallback. The engine does not remove the caller's DOM itself.

Reusable equivalents include `KitParticleDeleteContainerComponent` with static projection or a typed context template, forwarded element access, native attributes/events/styles, isDeleting and handleDelete; `createParticleDelete` replaces the React hook in an Angular injection context; `particleDelete` remains imperative. The controller merges defaults/overrides, guards overlapping requests and retains the hook's fallback callback behavior.

Angular destruction supplies cancellation absent from the React utility: an optional AbortSignal releases owned image listeners, fade timers, frames and overlay; restores interrupted element styles; and suppresses completion/deletion after destruction. A thrown completion callback rejects after canvas cleanup rather than leaving the native engine promise pending forever. The original React frame callback can throw before resolving its promise; the report does not claim that source failure is recovered. Main-list deletion otherwise retains source error ownership rather than inventing a transport or error banner.

Deterministic package evidence compares both actual exported engines with identical captured pixels, random streams and frame times. Nine exact operation comparisons pass across four patterns, desktop/mobile sampling, fractional dimensions, DPR capping and procedural capture fallback. Additional checks cover detached targets, pre-aborted requests, pending image listener disposal, interrupted fade/style restoration and active-frame/canvas disposal. All 24 browser cases pass: 16 behavior cases exercise real capture, card locking/removal, restore/reset and reusable callback order; eight paired layout comparisons cover default/empty/long-content/custom-padding states on desktop/mobile. Four shared light/dark consuming demo cases also pass. The focused package check verifies mount ownership/reset, destruction cancellation and complete source dependencies. See [batch evidence](batch-48-integration.md) for final gate status.

Source limitations are retained: the two named radial patterns use the original formulas, even though their names/comments suggest the reverse ordering. Physics is frame-step based with elapsed-time lifetime, not a refresh-rate-independent simulation. Fixed overlay bounds do not follow subsequent scrolling/resizing. Invalid negative sampling steps are not normalized; callers must supply valid options. No frame-rate, hardware acceleration, whole-DOM capture fidelity, full accessibility, cross-browser or SSR guarantee is claimed. Reduced motion fades preserve the source opacity semantics on successful completion.

Batch baseline passes: component/Angular sync; full production build with 289 SEO checks; all 117 unit tests; lint with 34 inherited warnings; focused package/source/disposal checks; and strict installed-tarball consumers on Angular 20.0.0, 20.3.33, 21.2.25 and 22.2.1, including all 116 selectors and both current usage recipes.
