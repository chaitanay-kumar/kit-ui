# Batch Gesture Tray parity (validated locally; integration pending)

React: `src/components/ui/BatchGestureTray.tsx`; authored definition: `scripts/angular-batch-gesture-tray.ts`; native types/styles/presence/gestures: `packages/angular/src/batch-gesture-tray-*`, `batch-gesture-tray.css`, `batch-tray-presence.ts`, `batch39-motion.ts`.

Selection uses controlled IDs when provided, otherwise internal state. A selection callback owns updates even without controlled IDs. Select-all compares array lengths, not membership; unknown or duplicate IDs are neither removed nor normalized. Enter/Space toggle role-checkbox items with default prevention; a global Escape listener clears whenever selection is nonempty. No outside-click dismissal or cancellation behavior is added.

Execution retains the original selected-array reference, action, completion callback and selection setter. Only action buttons disable during a pending action: item selection, select-all, dismissal and Escape remain available. Successful actions call captured completion, then clear through the captured setter. Action/completion/selection exceptions inside execution are silently caught and loading always resets; selection-callback exceptions from ordinary selection go through native ErrorHandler without cancelling the event. Failed operations preserve selection and remain retryable without an invented alert. The success color is styled as default, as in React.

The sticky toolbar retains its last rendered snapshot while exiting and reverses its spring on reopen. Check marks use 500/30/1; toolbar/row gestures use 380/30/.5; action gestures use 400/25/1. Rows also preserve the source's 200ms CSS transition over spring transforms. Paired pointer samples at approximately 140/350/600ms expose that extra delay. Held Enter, blur/release handling, primary mouse filtering, touch-hover suppression and selected checkbox hover styling follow actual Motion behavior. Source motion continues under reduced preference.

Native template/string icons replace React nodes. Items/actions remain required. Native destruction removes listeners, cancels frames and suppresses stale post-destroy completion/selection updates; the underlying application promise is not cancelled. This is a disposal adaptation: React can still invoke captured completion after unmount. Source toolbar live announcements and checkbox roles are preserved; no general accessibility conformance or physical-device coverage is claimed.

Packaged contracts pass identity, ownership, phantom-ID select-all, captured async callbacks, pending selection, failure recovery, Escape, exits and disposal. Desktop/mobile browser behavior and native demos pass. Dark/light geometry, typography, colors/radii, keyboard/pointer/touch and source-delay comparisons pass; see [batch evidence](batch-39-integration.md) for exact run scope and the source-listener readiness adjustment.

Batch 40 follow-up corrects owned SVG glyphs to the installed Lucide geometry and invokes captured completion callbacks unbound, as in React. The renewed packaged contract explicitly checks callback this is undefined; paired desktop/mobile SVG checks renew tray icons. See [batch 40 evidence](batch-40-integration.md).
