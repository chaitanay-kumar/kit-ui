# Animated File Upload parity

Validated baseline in batch 46. Integration review, merge/deployment and final user QA remain outstanding.

The native standalone Angular component replaces the Smart Upload proxy with this component's actual contract. Authoring lives in `scripts/angular-animated-file-upload.ts`; state, motion, icons and styles live in the `animated-upload-*` helpers and `animated-file-upload.css`. Default simulation is local; consumers provide `uploadHandler(file, onProgress): Promise<void>` for their own transport.

Initial files are mount-owned and do not auto-start uploads. Selection prepends or replaces files and caps visible rows, while all accepted incoming tasks start even when hidden by that cap. `accept` is a native picker hint; drops do not validate MIME/extensions. Oversize checks apply only to incoming files, and zero disables the size check. Single selection takes the first file. Disabled gates picker/drop but retains existing row actions. Custom progress remains unbounded and does not synthesize processing state.

Callbacks preserve source ordering, captured props and item identity. Selection and synchronous handler failures leave queued rows and prevent subsequent tasks/input reset. Custom completion receives the original uploading item even after its row is removed; completion exceptions become row errors. Retry receives the original failed item, retains stale attempt progress callbacks and intentionally omits custom completion callbacks. Default simulation advances every 180ms, uses processing 92 before completion, and completes with an updated item only when its row still exists. Removal does not cancel custom work or other simulation intervals while the component remains mounted.

Focused browser evidence: 48 passing desktop/mobile Chromium cases: 24 behavior (`parity-batch46-upload.spec.ts`), 12 paired layout/keyboard (`parity-batch46-upload-layout.spec.ts`), eight simulation/zero-cap/single-selection (`parity-batch46-upload-simulation.spec.ts`) and four drag/progress/layout/exit (`parity-batch46-upload-motion.spec.ts`). The paired layout checks compare measured row/drop/icon/text geometry and computed typography, color, border, spacing and radius against React for standard/compact layouts, all five statuses, disabled and maxSize zero. Motion checks cover drag scale/icon endpoints, progress width, sibling movement, immediate individual removal and retained final-list exit. These checks do not establish frame-by-frame trajectory equality under every interruption.

Fixture corrections: the drop observer moved outside React's delegation root; the motion selector now matches the row class as a complete token; the simulated clock explicitly flushes Angular rendering before querying the next file. Expected processing text uses the source's three periods. Renewed cases pass without changing production state/motion logic.

Deliberate disposal difference: native destroys owned intervals/frames and suppresses custom progress/completion after component destruction. React has no unmount cleanup and can invoke completion afterwards. While mounted, native preserves the source's row-removal and retry ownership. Source limitations are documented rather than silently changed: there is no live region, component springs have no reduced-motion bypass, and disabled does not disable row actions. Metadata now describes those actual boundaries.
